# hidane-flow 移植設計: 今日やる・今からやる・予実の自動計測

flicktasks に、hidane-tasks（別リポジトリ ~/dev/hidane-tasks）から選別した3要素を移植する設計書。

## 意図・背景

hidane-tasks は毎朝の予実管理アプリとして作り込んだが、分類やタブが増えて重くなった。
flicktasks の「開いた瞬間メモできる」身軽さを主役に据え直し、hidane-tasks で本当に価値があった
3つだけを持ち込む:

1. **今日やる** — メモの山から今日やるものを選び出す段階
2. **今からやる** — 1件だけに絞って着手する1点集中
3. **予実の見える化** — どれだけ時間を計画し、実際どれだけかかったか

鍵となる設計判断: **実績時間は手入力しない**。「今からやる」ステータスに居た時間を
自動計測する。フリックで着手・完了する普段の操作の副産物として実測が貯まる。
（hidane-tasks では「毎回実績を入力する運用は破綻する」と判断して実績を捨てた。
本設計はステータス滞在時間という入力ゼロの計測でそれを解決する）

## ゴール / ノンゴール / アンチゴール

- ゴール: 上記3要素が flicktasks の操作感（1ジェスチャー・ローカル先行・アニメーション）のまま使える
- ノンゴール（持ち込まない）: 4象限、週の計画、事業タグ、振り返りタブ、代表への報告コピー、
  カテゴリ分類、日次の計画モード（3択ウィザード）
- アンチゴール: 身軽さを損なうこと。起動後メモまでの操作が1つでも増えたら失敗。
  既存の SPEC.md 0章の設計原則はすべて維持する

## 1. データモデル（拡張）

```ts
// shared/types.ts
export const STATUSES = ["inbox", "today", "doing", "done"] as const; // "today" を挿入
export const STATUS_LABEL = { inbox: "メモ", today: "今日", doing: "今から", done: "完了" };

type Task = {
  // 既存フィールドはそのまま。以下を追加:
  estimateMin: number | null; // 見積もり分。null = 未設定
  actualMs: number; // 実測の累計ミリ秒。doing を離れるたびに加算
  doingSince: number | null; // doing に入った時刻(epoch ms)。doing 以外では null
  completedAt: number | null; // done に入った時刻。done 以外では null
};
```

- 経過時間の現在値 = `actualMs + (doingSince ? now - doingSince : 0)`。
  リロードしても localStorage / サーバーの `doingSince` から復元されるので計測は途切れない。
- ステータス遷移の副作用は純粋関数 `applyStatus(task, next, now): Task` に集約し、単体テストを書く:
  - doing に入る: `doingSince = now`
  - doing から出る: `actualMs += now - doingSince; doingSince = null`
  - done に入る: `completedAt = now`（doing からなら上の加算も行う）
  - done から出る（左フリックで戻す）: `completedAt = null`。actualMs は保持
- **doing は常に最大1件**（1点集中）。別のタスクを doing にしたら、既存の doing タスクは
  自動で today に戻る（actualMs を加算して）。store の flick / updateTask で強制する。
  ※サーバー側では強制しない（個人利用・単一端末前提。私の判断）

## 2. ステータス遷移（フリック連鎖の拡張）

```
inbox --右--> today --右--> doing --右--> done
inbox <--左-- today <--左-- doing <--左-- done
```

- 既存の `nextStatus`/`prevStatus`/`flick` は配列ベースなので STATUSES の差し替えでそのまま動く
  （store.flick 内のローカル `order` 配列は STATUSES を参照するよう直す）
- 端で跳ね返る挙動・フリック判定（88px / 550px/s）・退場アニメーションは既存のまま
- せり出しレイヤーの色: 前進は既存ルール（done へ=緑 / それ以外=空色）を維持し、
  doing へ だけ紫系（violet-200/70）にして「着手」を区別する（私の判断）。戻しは既存の琥珀

## 3. 画面構成の変更

既存のモバイル1画面構成（ヘッダー / コンポーザー / タブ / 一覧 / シート / トースト）は不変。変更点:

1. **ステータスタブは「メモ / 今日 / 完了」の3分割のまま**。doing はタブにしない
   （最大1件のためにタブを1枠使わない）。件数バッジ・スライドインジケータは既存どおり
2. **「▶ 今から」固定カード**をタブと一覧の間に追加。doing タスクがあるときだけ、
   どのタブを見ていても表示される:
   - 内容: ▶アイコン、本文（1行省略）、**経過時間（1秒ごとに更新、mm:ss または h:mm:ss）**、
     見積もりがあれば「/ 30分」を併記。超過したら経過時間を rose 系の色に
   - ガラスは `.glass-strong`＋アクセントリング（1点集中の主役感。私の判断）
   - フリック可: 右→完了（緑レイヤー）、左→今日に戻す（琥珀レイヤー）。タップでシート
   - 出現・退場はカードと同じ spring / 320ms 退場
3. **今日タブの上に予実サマリー行**（今日タブ選択中のみ、`.glass` の薄い1行）:
   - `計画 ○時間○分 ・ 実績 ○時間○分`＋計画に対する実績の細いプログレスバー
   - 集計対象: `status ∈ {today, doing}` の全件 ＋ `completedAt` が今日（ローカルタイム）の done。
     計画 = estimateMin 合計（未設定は 0）、実績 = 経過時間の合計
   - タスクが1件もなければ行ごと非表示（文言ゼロの原則）
4. **カードのメタ行**（既存: 相対時刻・ステップ進捗）に予実を追加:
   - 見積もりがあれば `30分` の小チップ
   - 実績があれば（actualMs > 0）`実 12分` を併記。done カードでは `見積30分 → 実45分` 形式
5. **詳細シートに「見積もり」段を追加**（優先度チップの直後）:
   - チップ 15 / 30 / 60 / 90 ＋ 数値入力（分）。選択中チップをもう一度押すと解除（優先度と同じ作法）
   - ステータス3分割は4分割になる（メモ/今日/今から/完了。インジケータは既存のスライド）

## 4. 同期・API・DB

- **migrations/0002_hidane_flow.sql**: SQLite は CHECK 制約を ALTER できないため、
  tasks テーブルを作り直してコピーする（新 status 制約 + estimate_min / actual_ms /
  doing_since / completed_at 列を追加）。既存インデックスも貼り直す
- API は器のまま: `POST /api/tasks`・`PATCH /api/tasks/:id`・import の zod スキーマと
  db.ts の行マッピングに新フィールドを追加するだけ。タイマーのロジックはすべてクライアント側
  （PATCH で計算済みの actualMs / doingSince / completedAt を送る）。サーバーは保存するだけ
- ゲスト→ログイン取り込み（import）も新フィールドをそのまま運ぶ
- **旧データの移行（私の判断）**: 旧仕様の "doing"（進行中・複数可）は新仕様の "doing"（今から・最大1件）と
  意味が違うため、**0002 マイグレーションで既存 doing を全件 today に落とす**。
  どれかを勝手にフォーカス枠へ昇格させない（1点集中は本人が選ぶもの）。タスクは消えず今日タブに現れる
- **読み込み時の正規化（保険）**: localStorage / サーバー / import から読み込んだ結果 doing が
  2件以上あったら、計測中（doingSince あり、同着なら updatedAt 最新）の1件だけ doing に残し、
  他は today へ正規化する（actualMs は規則どおり加算）。リロード時のタイマー継続（doingSince 復元）は
  この正規化で壊れない。削除 Undo など updateTask を通らない経路があるため、強制はロード時にも行う
- 上記以外の既存ローカルデータは新フィールドを既定値で補完
  （estimateMin: null / actualMs: 0 / doingSince: null / completedAt: null）

## 5. 変えないこと

- SPEC.md 0章の設計原則すべて（開いた瞬間メモ・1ジェスチャー・ローカル先行・機能ラベルのみ・動きで伝える）
- コンポーザーの挙動（3章）一式。追加先は inbox のまま
- 詳細シート・削除 Undo・AI整理（適用先フィールドも既存のまま）・認証・ゲスト同期の仕組み
- ビジュアル言語（10章: Liquid Glass・色・角丸・アニメーションパラメータ）。新規要素もこの語彙で作る

## 6. 受け入れテスト（E2E。既存 e2e/app.spec.ts に追加・修正）

既存テストのうちステータス連鎖に依存するもの（SPEC 11章の 6 など）は新連鎖に合わせて更新する。追加:

1. 右フリック連鎖 inbox→today→doing→done、左で逆順。done で右・inbox で左は跳ね返る
2. タスクを doing にすると「▶ 今から」固定カードが現れ、経過時間が進む（1秒以上待って表示が変わる）
3. 別のタスクを doing にすると、先のタスクは today に戻り、固定カードは新しいタスクになる（常に1件）
4. 固定カードを右フリックで done になり、カードのメタに実績が残る。リロードしても actualMs が残る
5. シートで見積もり 30 を選ぶ→カードに「30分」チップ。もう一度押すと解除
6. 今日タブに予実サマリー行が出て、計画・実績の数字が正しい（today 2件 + done-today 1件で検算）
7. doing のままリロードしても計測が継続している（doingSince 復元）
8. ゲストで作った見積もり・実績がログイン取り込み後も保たれる
9. 既存テスト（起動フォーカス・IME・追加・シート・削除 Undo・401）がすべて通り続ける

## 7. ビルダーに委ねること

- 固定カードと予実サマリーの正確な余白・フォントサイズ（既存の語彙に合わせる）
- 経過時間表示の tick 実装（doing があるときだけ 1s interval、なければ止める）
- E2E でのタイマー検証の待ち方（実時間 1〜2 秒待つか、Date モックか。既存 helpers の流儀に合わせる）
